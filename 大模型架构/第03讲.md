# Lecture 3: Training Deep Networks

## Training Deep Networks

Deep training has three recurring problems: optimization can be slow, gradients can vanish or explode across layers, and a model can memorize training samples without generalizing. This lecture addresses them through optimizers, initialization, regularization, normalization, and careful tuning.

| Problem | Why it happens | Main tools |
| --- | --- | --- |
| Slow or unstable updates | A single learning rate does not fit every parameter or direction. | Momentum, RMSProp, Adam, AdamW, and learning rate schedules. |
| Weak gradient flow | Repeated derivatives can shrink or grow rapidly across layers. | Xavier or He initialization, residual connections, and gradient clipping. |
| Overfitting | The model fits training details that do not hold on new data. | Weight decay, dropout, augmentation, and early stopping. |
| Shifting activation statistics | Intermediate feature distributions change during training. | Batch normalization and its training versus inference rules. |

The aim is to reduce training loss while maintaining reliable validation performance. Each intervention should be evaluated against a clear baseline.

## AdaGrad → RMSProp: A Step Size per Parameter
AdaGrad (2011)
sum every squared gradient
s = s + g * g
θ = θ - η * g / (√s + ε)
s only grows → steps shrink to zero
RMSProp (2012)
exponential moving average
s = ρ * s + (1 - ρ) * g * g
θ = θ - η * g / (√s + ε)
old gradients fade (ρ = 0.9 or 0.99)
Back in the ravine: the y-gradient is 50× larger and is divided by a √s that is 50× larger — both directions take similar steps. The bowl becomes round.
Trivia: RMSProp was never published — it comes from one slide of Hinton’s 2012 Coursera course.

## Adam = Momentum + RMSProp (+ Bias Correction)
m = b1*m + (1-b1)*g # momentum
v = b2*v + (1-b2)*g*g # RMSProp
m_hat = m / (1 - b1**t) # bias
v_hat = v / (1 - b2**t) # correction
θ = θ - η * m_hat / (√v_hat + ε)
- m̂ / √v̂ ≈ ±1: every step has length ≈ η, whatever the gradient’s
scale.
- Scale-free → the default 1e-3 often just works.
- Tiny gradients on a plateau still give full-size steps.

## Bias Correction: Why Divide by 1 − βᵗ?
m₀ = v₀ = 0, gradient always g = 1
m₁ = 0.1 · 1 = 0.1 (true: 1)
v₁ = 0.001 · 1 = 0.001 (true: 1)
m₁/√v₁ = 0.1/0.0316 = 3.16
m̂₁ = 0.1/0.1 = 1, v̂₁ = 0.001/0.001 = 1 ✓
step t 1 − β₁ᵗ 1 − β₂ᵗ m / √v (raw) m̂ / √v̂

Why it matters: β₂ is closer to 1, so v is biased toward 0 far more than m. Uncorrected Adam takes early steps 3–6.5× too large. Dividing by 1 − βᵗ makes both estimates unbiased from step 1, and fades to ×1 by
itself.

## Adam in numpy: A Drop-In for Lecture 2’s Update Line
class Adam:
def __init__(self, params, lr=1e-3, b1=0.9, b2=0.999, eps=1e-8):
self.p, self.hp, self.t = params, (lr, b1, b2, eps), 0 self.m = [np.zeros_like(p) for p in params]
self.v = [np.zeros_like(p) for p in params]
def step(self, grads):
lr, b1, b2, eps = self.hp; self.t += 1
for p, g, m, v in zip(self.p, grads, self.m, self.v):
m[:] = b1 * m + (1 - b1) * g # momentum
v[:] = b2 * v + (1 - b2) * g * g # RMSProp
mh, vh = m / (1 - b1**self.t), v / (1 - b2**self.t)
p -= lr * mh / (np.sqrt(vh) + eps) # in place
Checked against torch.optim.Adam: identical to 7 digits. Project 1 bonus idea: try it, note one observation.

## AdamW: Weight Decay Is Not L2 (Inside Adam)
SGD: θ ← θ − η(g + λθ) = (1 − ηλ)·θ − η·g
with plain SGD, L2 and weight decay are the same thing — every weight shrinks by the fraction ηλ each step Adam + L2 (coupled)
g = g + λ * θ
θ -= η * m_hat / (√v_hat + ε)
The decay rides inside m and v and is divided by √v̂
— weights with big gradients are barely decayed.
AdamW (decoupled)
θ -= η * m_hat / (√v_hat + ε)
θ -= η * λ * θ
Decay applied directly, outside m and v: every
weight shrinks by the same fraction.

## The Update Line, Upgraded — in PyTorch
opt = torch.optim.AdamW(model.parameters(), lr=1e-3,
betas=(0.9, 0.999), weight_decay=0.01)
warm, total = 500, 20_000
def lr_mult(step): # warmup, then cosine to 10%
if step < warm: return (step + 1) / warm
t = (step - warm) / (total - warm)
return 0.1 + 0.9 * 0.5 * (1 + math.cos(math.pi * t))
sched = torch.optim.lr_scheduler.LambdaLR(opt, lr_mult) for x, y in loader:
loss = F.cross_entropy(model(x), y)
opt.zero_grad(); loss.backward()
opt.step(); sched.step() # the new update line

## Interview Answer Card: Lecture 3 (1/2)
ANSWER PATTERN: CONCLUSION → INTUITION → TRADE -OFF
Q1 Write Adam’s update. What does bias correction do?
m, v = EMAs of g and g²; θ −= η·m̂/(√v̂ + ε). m, v start at 0 → biased low (v more) → early steps too big; ÷ (1 − βᵗ) makes them unbiased, fades to 1.
Q2 AdamW vs. Adam + L2?
Adam + L2 puts λθ into g, so the decay is divided by √v̂ — busy weights barely decay. AdamW subtracts ηλθ directly: uniform. Identical for SGD, not for Adam.
Q3 Why does BN work? Inference? Tiny batches?
Standardize per feature over the batch, then γx̂ + β → smoother landscape, larger η. Inference: running mean/var. Tiny batch: noisy stats → SyncBN, or GN / LN.
Q4 What does dropout do at inference?
Nothing — it is off. Inverted dropout already scaled survivors by 1/(1 − p) in training, so expectations match.
Switch with model.eval().

## Interview Answer Card: Lecture 3 (2/2)
ANSWER PATTERN: CONCLUSION → INTUITION → TRADE -OFF
Q5 Why not zero init? Xavier vs. He?
Zeros: symmetric units never differ. Keep each layer’s variance: Var(w) = 1/d_in (Xavier, tanh) or 2/d_in (He,
ReLU — ReLU halves the variance).
Q6 Vanishing / exploding gradients: why, and fixes?
Backprop multiplies one factor per layer: < 1 vanishes, > 1 explodes. Fixes: ReLU, careful init, normalization, residuals, gating; clipping for explosions.
Q7 How does gradient clipping work?
If the global norm ‖g‖ > c, rescale g to length c — direction kept (by value would change it). LLMs use c = 1.0. It cannot cure vanishing.
Q8 Diagnose overfitting; how do you tune?
Train loss low, val loss rising → more data, augmentation, L2, dropout, early stopping. Tune η first, log scale, one change at a time; random > grid.
